## The engine

Likely the loop is concrete example → build a useful project → ask peers for help → share a finished result that inspires another builder. The template catalogue provides starting points, the community hub supports building, and pricing permits a free first attempt. This is a proposed explanation of the visible surfaces, not a measured referral coefficient. [E2, E3, E4]

The public pricing page describes an AI software engineer for web apps built through conversation. Likely a founder should copy one sharply bounded job before copying the breadth of that promise. [E2]

## Steal this playbook

Your playbook, ranked by expected impact per effort for this brief; numbers are proposed experiments, not Lovable benchmarks. [E9]

1. **Make one consultant portal template.** First step: publish a working example with sample clients. Watch template visit → completed project. Likely this reduces blank-page hesitation. [E3, E5]
2. **Publish three task pages.** Start with client portal, proposal tracker and onboarding checklist, each linking a runnable example. Watch nonbrand impressions and first builds by page. [E3, E7]
3. **Show one complete build each week.** First step: record the starting prompt, edits and final usable result. Watch viewers who open the template and finish a build. [E3, E4]
4. **Make the first success free and bounded.** Start by costing one portal build and stating that allowance plainly. Watch activation and cost per activated user. [E2]
5. **Run one small build-along after users arrive.** First step: publish a workshop outline using the same template. Watch completed projects and seven-day return use. [E4]
6. **Close the feedback loop weekly.** First step: record the three most common first-run failures and fix one each week. Watch repeat completion and support burden. Likely this is more useful early than expanding template count. [E4, E5]
